# DB MCP Tools 使用指南

DB MCP Tools 将数据库连接、Agent 身份、权限、审批、脱敏与审计放在独立 Go Server 中。桌面客户端用于管理，同一会话只连接一个 Profile。独立后台进程与系统服务持续运行；启用“Server 随客户端启停”的环境在真正退出客户端时停止本次启动的实例。

## 选择安装包

- **纯客户端**：连接已有 Server，或选择已安装的 `dbmcp`。没有本机程序时使用 HTTP 接入 Agent。
- **携带 Server**：包含匹配平台的 Go 程序。设置页可直接部署、启动并连接。
- **独立 Server**：一个程序同时提供 Server、管理 CLI、STDIO Bridge 和服务管理。

版本、API、平台、驱动、文件哈希和第三方许可见包内清单。本地安装包未签名。默认构建包括 PostgreSQL、MySQL、SQL Server；明确标为 `dm-local` 的本机构建另含 DM8 原生驱动，其重新分发许可尚未确认，不将其称为已获授权的公开分发包。

Windows v1.0.4 默认应用目录为 `%LOCALAPPDATA%\db-mcp-tools`。从旧 `DB MCP Tools` 目录升级时，安装器自动迁移到同父目录的 `db-mcp-tools`，保留连接档案、凭据、Server 数据与自启动设置，并修正快捷方式。已自定义的目录继续保留；也可手动选择空目录。目标有其他文件时安装器会拒绝覆盖；旧目录中不属于旧安装清单的文件保留原位。迁移失败可重跑安装器，并通过诊断包中的 `installer-migration.log` 定位。

## 第一次运行

1. 点击侧栏“当前环境” → 新建环境，选择“本机托管”或“已有 Server”。本机模式选择 `dbmcp`；新环境的数据目录可留空，由客户端创建独立目录。携带包会自动发现程序。不要选择项目根目录或其他应用的数据目录。
2. 保存环境，在设置 → Server 启动并连接；勾选“Server 随客户端启停”则在进入该环境和下次打开客户端时自动启动。程序部署到数据目录的 `runtime/versions/`，保留稳定入口。新环境自动选择可用回环端口，已有 `deployment.toml` 的地址保持不变，MCP 地址以 Server 实际配置为准。
3. 在“数据库实例”的连接页填写账号并测试连接。默认数据库仅用于建立连接和发现对象：PostgreSQL 默认 postgres，SQL Server 默认 master；MySQL 没有通用默认库，可留空；DM8 从端点识别实际库名。在范围页从左侧远端对象多选，用 → 移入右侧许可对象，用 ← 移除。可选整库、模式、表或字段，新建实例初始没有对象授权。再配置操作和审批并保存；实例策略是上限，实体绑定只能进一步收紧或追加 Mask。
4. 在设置 → Agent 接入安装配置。Agent 首次连接后自动生成待授权实体，可点击访问实体卡片上的“去授权”，直接定位到待审批 → 实体登记，确认实例与权限，再让 Agent 重新连接。也保留在访问实体页手动创建、签发和绑定的方式。

独立运行示例：

```sh
dbmcp --data-dir <专用目录> init
dbmcp --data-dir <专用目录> runtime upgrade --start
dbmcp --data-dir <专用目录> run status
```

数据和程序分开保存。Windows 默认 `%LOCALAPPDATA%\DBMCP\server`；macOS 默认 `~/Library/Application Support/DBMCP/server`；Linux 默认 `$XDG_DATA_HOME/dbmcp/server` 或 `~/.local/share/dbmcp/server`。部署设置在 `deployment.toml`，修改监听地址前先停止 Server。

连接已有 Server 时，在环境编辑中填写回环 Admin 地址与管理员凭据；远程部署通过 SSH 隧道管理。已有 Server 模式只连接，不控制其进程。设置 → Server 展示当前目标，不以并列 Tab 保存两套连接。

## 环境与会话

Profile 是本地环境配置，无软件登录账号或密码。初次启动自动创建名为 `default` 的环境，保持未连接，可编辑后选择连接方式。侧栏始终显示唯一当前环境及连接状态，可新建、编辑、切换和删除。编辑已连接环境前先断开；删除仅移除客户端配置和保存凭据，不删除 Server 数据。切换关闭未保存的业务表单，清除旧缓存、审批通知和事件订阅；存在进行中的操作时拒绝切换，完成后重试。失败保留实际断开状态，不自动重放业务写入。

主题、通知、关闭行为和自动轻量模式随 Profile 保存；系统登录自启动、安装位置和版本由应用共用。业务数据与权限保存在 Server，两个 Profile 指向同一 Server 时共享其业务状态。管理员凭据按 Profile 分开存入系统 keyring。

“Server 随客户端启停”默认关闭，要求本机程序 1.0.10 或更新。进入环境时启动；切走或真正退出时，仅停止本次客户端启动且进程身份仍匹配的后台实例。托盘与轻量模式继续运行。外部已启动实例先手动停止或关闭此选项；系统服务不能启用此选项。停机失败保留错误，可重试或选择“保留 Server 并退出”。异常崩溃、强制终止无法执行优雅停机，下次启动会按外部运行实例处理。

升级自动将旧连接迁移为 `default` 环境，保留原目录、地址、身份和偏好，默认不启用随客户端启停。旧配置与凭据仍保留，首次打开界面迁移主题和通知。备份恢复与配置导入导出位于“数据管理”。

## 接入 Codex / Claude Code

设置 → Agent 接入 → 安装 MCP 配置，选择用户 / 项目作用域、HTTP / STDIO 和条目名称，然后预览。此时无需预先创建实体或选择实例。

- Codex：用户 `$CODEX_HOME/config.toml`，未设置时为 `~/.codex/config.toml`；项目 `.codex/config.toml`，仅受信任项目加载。
- Claude Code：默认用户 `~/.claude.json`；项目 `.mcp.json`。项目 MCP 首次需 Claude Code 自身确认。
- HTTP 使用各客户端实际支持的认证字段；STDIO 使用稳定 `dbmcp` 路径和受限凭据文件。纯客户端可选择独立安装的程序。

安装只签发此配置专用的接入凭据，备份原文件并原子保存。Agent 首次携带该凭据连接 MCP 时，Server 原子创建待授权实体，返回 `entity_pending`；批准前不能发现数据库或调用数据工具。在待审批 → 实体登记选择实例、资源、操作与限额后批准，Agent 重新连接即可使用原凭据。绑定与实体启用在同一事务提交，失败不留下部分授权。

实体根据配置中的独立随机凭据识别，不根据可变、可伪造的 IP 或客户端名称认定身份。同一凭据重试、并发或重连只生成一个实体；复制同一配置会共用身份，需要区分时分别安装。未知请求不会匿名创建实体。拒绝登记会撤销该接入凭据，不能靠重连重新注册。

安装失败会撤销新接入凭据。同名外部条目不覆盖；文件变化后需要重新预览。JSON 的无关值、TOML 的无关段落与注释及原换行保留。项目文件含凭据时不要提交版本库。

安装后重启 Agent 或重新连接 MCP。工具包括 `list_instances`、`list_databases`、`list_schemas`、`list_tables`、`describe_table`、`db_query`、`db_execute`、`db_explain`、`approval_status` 和 `resume_request`。

移除只删除未被改写的自身条目，并撤销安装凭据。用户已修改的条目保留，旧凭据仍会撤销。轮换其他凭据后需更新相应 Agent 配置；Token 仅签发时显示。

其他客户端可在“访问实体”签发或轮换凭据后，填写 MCP 地址并点击“导出通用 MCP 配置”。导出的 JSON 使用 `mcpServers` 与 HTTP `headers`，适用于支持该格式的客户端；按目标客户端的导入说明使用。文件包含当前实体凭据并设置为私密权限，覆盖既有文件前保存备份；该凭据的权限、轮换与撤销继续由 Server 管理。

## 权限、审批与 Mask

资源和操作取实例与绑定的交集；来源 CIDR 同时满足；限额取较小值。默认读查询放行，写入询问；DDL、过程、动态 SQL、多语句和未知来源拒绝。审批不能解除硬拒绝。

一个实例可许可一个、部分或全部数据库。PostgreSQL、SQL Server 的对象层级为数据库 → 模式 → 表 → 字段；MySQL 数据库与 Schema 同义，直接展示数据库 → 表 → 字段；DM8 一个端点对应一个实际数据库，内部按用户／模式 → 表 → 字段选择。空模式也可授权，包含以后创建的对象。数据库列表受连接账号自身可见性限制。

Agent 先调用 `list_databases`，再向 `list_schemas`、`list_tables`、`describe_table`、`db_query`、`db_execute` 或 `db_explain` 传入精确的 `database` 名称。每次请求只选择一个库，不支持 USE 或跨库 SQL；多库省略目标会拒绝，DM8 可推断端点的唯一实际库。只许可一个库时既有省略目标的方式继续可用。范围页支持未保存连接的发现；保存后授权生效。修改默认连接库不会改变对象授权。审批和记住的规则只适用于记录的数据库。此对象选择界面要求 Server 1.0.2 或更新版本。

选择上级包含其当前和未来下级，移入上级会合并重复的子项；缩小范围时先移除上级再选择下级。Ctrl / ⌘ 或 Shift 多选，方向键导航、空格选择。树按库展开时读取结构，连接或远端对象变化后用“刷新对象”重读。表较多时可直接选择库或模式，当前版本未提供树内搜索或虚拟滚动。

选择器生成含数据库的资源键：整库为 `db/<库>/*`，模式为 `db/<库>/<模式>.*`，表为 `db/<库>/<模式>.<表>`，列为 `db/<库>/<模式>.<表>.<列>`。名称内的点号、百分号、通配符及斜线等保留字符自动编码。旧 `schema.table[.column]` 规则仍对已配置数据库统一生效；编辑旧单库／部分库实例时，界面把它们转换为对应库的明确资源键。实体绑定的 `*` 只表示实例范围内的全部对象。

Agent 写入返回 `pending` 时，在“待审批”查看 SQL、参数、来源和范围，选择允许一次、拒绝或记住明确的表与操作范围。`always` 策略需显式调整后才能记住。随后 Agent 用原 `request_id` 调用 `approval_status` / `resume_request`，不能替换 SQL。并发重试只认领一次；提交结果未知的写入不自动重放，应先检查目标库。

实例 Mask 始终先于实体追加规则；禁止列在条件与表达式中也不可访问。敏感来源参与派生表达式时整值替换。不提供独立的内置内容检测，按需使用 Mask 的正则替换。用规则预览和实体模拟器检查实际 Server 行为；模拟器不执行 SQL。

“可访问的表与字段”限制数据范围：例如 `public.orders` 允许该表，`public.users.email` 允许该字段，`*` 表示当前实例内全部数据；能否查询或写入还取决于操作权限。新建实例、实体绑定和模板的 Mask 均为空，不预置任何规则；只有手动添加或显式选择模板时才带入规则。规则预览需要指定 Schema、表、字段和示例值，只应用匹配来源的规则。

内容替换统一配置在 Mask 中：字段或模式指定匹配范围，处理方式选择“正则替换”，再填写表达式与替换值。升级后旧的内容检测开关不再生效；已有显式 Mask 规则保留，可在 Mask 页删除不需要的旧规则。

SQL 支持范围见 [依赖与限制](dependencies.md)。PostgreSQL Explain 只返回不执行的结构与估算；其他方言不开放计划工具。DM 本版原生库不能强制并验证客户端 TLS，仅接受显式关闭 TLS 的本机或受保护隧道连接。

## 运行与系统服务

携带 Server 的客户端安装更新后，首次启动会检查保留的本机连接档案。若档案使用该数据目录的受管稳定入口、Server 身份匹配、随包程序版本更新，则调用 Go 升级协调器：停止受管进程 → 备份／迁移 → 部署新版本 → 恢复原运行状态 → 自动重连。保留数据会保留实例、密码、实体、凭据和审批状态，不会把运行程序固定在旧版。停止的 Server 不会因此自动启动；系统服务升级仍可能出现系统 UAC。

远程 Server、自选的外部程序及纯客户端不自动替换，需先断开，在环境编辑中选择新版程序，再到 Server 设置升级。新客户端要求 Server 至少 1.0.2，版本不足时显示明确提示并阻止业务请求；可在设置查看运行版本与随包版本。升级失败时查看诊断和保留的恢复快照，不反复卸载或删除数据。

未启用随客户端启停时，“退出客户端”与“停止 Server”是不同操作。客户端登录自启、关闭到托盘、Server 服务自启分别设置。前台运行由原终端控制；后台可用 `run start|stop|restart`。已注册服务的数据目录拒绝另启后台模式。

Windows 设置页可预览并迁移到 `%PROGRAMDATA%\DBMCP\server`，使用 LocalService；系统拥有 UAC 授权窗口，应用不代为批准。源目录和恢复快照保留。macOS / Linux 默认当前用户 LaunchAgent / systemd 服务；系统级 CLI 使用 `--system --user <非 root 账户>` 并由平台管理员授权。

```sh
dbmcp --data-dir <目录> service install
dbmcp --data-dir <目录> service start
dbmcp --data-dir <目录> service status
dbmcp --data-dir <目录> service stop
dbmcp --data-dir <目录> service uninstall
```

Windows 未指定数据目录的服务命令默认系统目录。卸载服务保留数据和稳定程序。桌面卸载不停止外部 Server；保留应用数据时已安装的 Bridge 凭据文件继续存在。

## 升级与恢复

设置页选新程序并点击“备份并升级”，或运行新构建：

```sh
new-dbmcp --data-dir <目录> runtime upgrade
```

升级停止受管进程、备份、部署新版本，更新既有服务注册并恢复原模式。稳定入口指向 `current.json`，旧程序和 `previous.json` 保留。迁移到空目录可用 `runtime migrate --to <目录> --start`；加 `--service` 转为服务。源目录保持停机。

完整备份包含 SQLite 一致性快照、配套密钥、管理员凭据及哈希清单；默认每日备份并保留最近七份备份。配置导出不含秘密，导入创建新的停用对象，不覆盖现有状态。

```sh
dbmcp --data-dir <目录> backup
dbmcp --data-dir <目录> restore <备份目录>
```

恢复必须停机，验证清单与 SQLite 完整性，恢复前保存现状快照。升级失败后检查服务 / `server.log`，使用错误中保留的快照明确恢复；不自动回滚可能已被 MCP 客户端使用的状态。需要回退程序时，停机后执行 `runtime rollback-program`；既有系统服务需重装以跟随程序路径。不要将新 schema 直接交给旧程序。

## 远程部署与故障定位

在访问日志中点击某行或“查看详情”，右侧抽屉显示请求概览、完整 SQL、绑定参数、执行摘要、匹配的 Mask 规则与关联事件。可切换上一条／下一条、复制请求 ID、刷新或“导出该请求”；筛选、分页与列表滚动位置保持。抽屉内容独立滚动，标题和操作栏固定，Escape 关闭。

从 1.0.8 起，Server 把数据库请求详情加密保存在状态库，按 30 天审计保留期清理；这份历史不会供 Agent 恢复执行，原执行载荷仍按原规则清理。单次请求导出包含已保存的 SQL 和参数以及关联事件，结果只保存行数、影响行数、字段、截断与错误等摘要，不保存结果行原值。旧请求缺少内容时明确显示“未记录”或“已清理”，不能还原已删除内容。管理操作展示自身审计记录。

1.0.8 新建策略默认最多返回 5000 行、10485760 字节；新建连接的 TLS 默认“关闭”。已有实例和模板的显式配置保留。已设置的连接密码固定显示六个黑点作为提示，留空保存会沿用原密码，输入新密码才替换。进入页面或打开弹窗时不自动强调输入框或按钮，Tab 导航仍可用。

Admin 仅绑定回环，远程管理通过 SSH 隧道；MCP 非回环部署要求 TLS 或明确配置反向代理。客户端 Admin 凭据在系统 keyring 中，Agent 凭据不能调用管理 API。

反向代理部署在 `deployment.toml` 配置 `reverse_proxy = true` 与 `trusted_proxies = ["127.0.0.1/32", "::1/128"]`，仅列出真实代理的 IP / CIDR。代理应覆盖或追加 `X-Forwarded-For`，并限制直连后端。Server 仅当连接来自可信代理时，从右向左剥离可信跳点；缺失、无效或全为可信地址的链拒绝认证。未配置可信代理时忽略转发头，Admin 始终只看真实连接。

连接失败先检查版本、驱动清单、地址、运行方式和数据目录。端口占用不会触发杀进程；复制凭据到另一目录不能停止原 Server。设置 → 通用、访问日志页和托盘右键菜单均可导出诊断包；断连仍可导出本地证据，远端日志不可用会注明。Server 主机可执行 `dbmcp --data-dir <目录> diagnostics --out <新文件>.json`。路径、保留规则与定位方式见 [日志与诊断](diagnostics.md)。

首次关闭窗口询问最小化到托盘或直接退出，可勾选“不再提醒”；通用设置中可随时修改。轻量模式在最小化到托盘时释放主窗口及 WebView，打开时重新加载，未保存表单不保留。托盘提供打开主窗口、导出诊断包和退出；也可从开始菜单再次启动来唤回。关闭或退出客户端都不停止独立 Server。
